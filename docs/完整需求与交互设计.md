# 轻舟 TrailDrop：完整需求与交互设计

版本：0.1.3 · 整理日期：2026-10-23 · 状态：Mac 测试版已实现，Windows 与 Android 处于规划阶段。

本文综合原始项目交接材料、本轮用户补充、已运行的代码和实机验证。交接材料中的开发指令只作为历史背景；产品要求以用户在本轮明确的选择和当前可验证行为为准。

## 1. 产品定义与范围

轻舟帮助用户从运动相机、读卡器等影像设备把照片和视频**单向转存**到自己选择的保存位置，尽量保留原画质、原文件名和关联文件。扫描与转存不会自动删除设备原文件。用户需要腾出设备空间时，进入独立的“设备清理”页面操作。

本阶段的可运行产品是 macOS 原生应用，支持能在 Mac 上挂载为普通磁盘的 USB 相机存储和读卡器，也支持手动选择本地目录作测试。Windows PC 和 Android 的目标路径目前只是交互规划，尚无这两端的应用、传输协议或实际转存功能。iOS 尚未列入实施范围。

### 1.1 用户与核心场景

| 用户场景 | 需要完成的事 | 成功结果 |
| --- | --- | --- |
| 一次旅行后整理素材 | 找到设备、查看全部素材、按需勾选 | 能看见真实媒体与来源路径，选定后复制到 Mac |
| 只带走近期素材 | 选最近 1 天、3 天或自定义时间 | 范围内素材有明确选中标记与数量 |
| 设备快满了 | 查明哪些素材已有有效副本，再清理 | 普通清理前重新校验；未备份清理须二次确认 |
| 在不同平台使用 | 理解相同的归档目录如何落到 PC、手机 | 当前只展示规划；以后各端再实现实际复制 |

### 1.2 交付边界

- Mac 应用离线运行，无需登录或上传云端。安装包内含文件引擎，终端用户无需安装 Python。
- 支持 DJI Osmo Action 4 已挂载 USB 存储的发现与只读扫描。该实测结果不能推断其他品牌、所有格式或真实设备写入已完成验收。
- MTP/PTP、Wi‑Fi、蓝牙和云端同步不在当前 Mac 实现范围。
- 安装包使用临时签名，尚未进行 Apple Developer ID 签名与公证；正式分发是后续工作。

## 3. 信息架构与视觉

主窗口采用 Mac 原生侧栏与内容区。侧栏始终可见三个功能入口与已发现的外接存储；顶部显示当前来源、扫描按钮、手动选择按钮和重新扫描。内容区的路径预览位于素材列表上方；底部固定操作区展示状态、目标目录、数量和主按钮。清理页沿用素材展示，但主操作切换为清理确认。

### 3.1 图标和界面视觉

- 应用图标：深海绿圆角底色 `#07524F`，浅色船帆与船身 `#F7F3EA`，青绿帆内片 `#2FBAA7`，金色船首 `#EFAE50`。船象征“轻舟”，船首方向表达从设备带走素材。SVG 是设计源文件，构建时生成不同分辨率的 Mac 图标。
- 界面采用 SwiftUI 系统文字与 SF Symbols，遵循系统浅色和深色外观。蓝绿色用于选择和主要操作；危险操作配文字说明和确认流程。
- 视觉层级优先保留素材列表的可见空间。来源与 Mac 路径直接显示，PC/手机规划路径可展开。

## 4. 通用设备扫描流程

1. 用户接线并在相机上启用文件传输，使设备作为 macOS 可读取磁盘挂载。
2. 点击“扫描已连接设备”。应用列出外接物理存储；一个候选设备直接扫描，多个候选时让用户选。磁盘镜像不作为相机候选。
3. 无候选设备时，说明可检查 USB 模式或使用“选择设备目录”。手动目录既可选设备根目录，也可选 DCIM 或测试目录。
4. 扫描递归查找支持的媒体，读取文件元信息与关联文件，并检查历史 Mac 副本是否仍有效。
5. 扫描结果显示素材数、已验证 Mac 副本数、日期分组和可用预览。**扫描本身不复制、不删除。**

### 4.1 素材卡片

卡片展示真实缩略图或不可预览说明、文件名、设备内相对路径、拍摄时间、大小、是否已有有效 Mac 副本、关联文件数及时间来源。视频卡片有播放标记。缩略图点击进入单项预览，勾选标记只负责选择；“查看路径”只切换路径示例，不改变选择。系统无法解码的原始格式仍可原样转存，并可调用外部应用打开。

## 5. 批量转存

1. 扫描后展示设备内全部识别到的媒体，包括已有副本的项目。按日期倒序分组，组内按拍摄时间正序。当前实现默认选中扫描结果；用户可逐项、逐天、全选或取消全选。
2. 在底部选择 Mac 保存目录。路径预览展示当前素材完整来源路径和预计目标路径。选中的素材数、预计待复制数、容量和可跳过数随选择及目标目录变化。
3. 用户点击“开始 / 继续转存”。执行时重新校验源文件身份，复制媒体和已识别的关联文件，写入临时文件，计算 SHA-256 并验证目标。已在**当前目标目录**内的有效副本可跳过。
4. 完成后更新实际 Mac 副本位置，保留设备原文件。暂停、中断或掉线后保存断点；恢复时验证已写入前缀。

预估数只是扫描时的信息，最终复制、跳过与失败以执行时的校验结果为准。更换目标目录时，不应把其他目标目录的副本误算成当前目录可跳过项。

## 6. 全量自适应转存

本页自动选择范围内全部素材，卡片上的选中标记只读。可选“全部素材”“最近 1 天”“最近 3 天”“自定义时间”：最近天数按本机时区的自然日计算，自定义范围包含结束分钟。UI 显示具体范围；开始晚于结束时阻止执行。需要排除个别素材时，用户转到批量页调整。

路径预览跟随当前范围和所查看的素材变化。复制、校验、目标目录、去重和保留源文件规则与批量页相同。范围外素材不会参与本次转存。

## 7. 路径预览与归档规则

### 7.1 当前可执行的 Mac 路径

路径预览以一件素材为例，直接显示其设备绝对路径与 Mac 预计保存位置。顶部标出该示例是否属于当前选择。没有素材可展示时，先显示设备来源目录与 Mac 保存根目录。

```text
设备原文件：/Volumes/<设备名>/DCIM/.../<原文件名>.MP4
             ↓ 单向转存，源文件保留
Mac 目标：   <用户选择的目录>/<转存时间_短码>/<拍摄日>/<时-分>/<来源目录名>/<设备内相对路径>
```

例如批次文件夹为 `2026-10-23_14-35-08_a1b2c3`；其确切名称在转存开始时生成。若素材在当前目标目录内已有有效副本，预览显示该副本的实际路径并说明预计跳过。若副本在其他 Mac 目录，单独显示原有位置，同时显示这次所选目标的预计位置。断点恢复时也可能继续使用已有任务的批次路径；最终路径以完成后的记录为准。

### 7.2 未来平台的路径规划

展开区域展示 Windows 风格的 `<PC 保存目录>\...` 与手机文件目录 `<手机文件目录>/...`。两端计划沿用“批次 / 拍摄日 / 时间 / 来源 / 相对路径”的结构，并保留原文件名。占位符不是实际选择结果，也没有表示 Mac 已经把素材推送到这些设备。Windows 与 Android 需要各自实现本地选择目录、设备访问、复制、校验、断点及权限处理后才可称为可转存。

本产品当前的“同步”含义是设备到本机目标的单向转存。不会因为 Mac 副本或清理操作而反向修改另一端设备。

## 8. 设备清理与安全边界

清理页保留全部设备素材，让用户区分已验证副本和未备份或副本不可用的项目。普通清理要求执行时重新校验设备原文件及整组关联文件，并验证 Mac 副本内容匹配；通过后只删除用户明确选择的设备侧文件。Mac 副本不删除。

含未备份素材的选择改用“强制清理”，先列出风险和清单，再要求输入 `删除未备份素材` 才能执行。取消任一步均不删除。强制模式只跳过备份门槛，仍须执行来源身份与路径安全校验。多文件组删除不具备文件系统级原子性，中断后需重新扫描并报告实际结果。

清理与转存是两个独立操作，不因转存成功自动清理。真实相机数据的删除风险高，应先用可丢弃的测试素材验证该型号的关联规则。

## 9. 文件格式、时间与数据一致性

当前识别的媒体扩展名包括 MP4、MOV、MKV、AVI、INSV、INSP、JPG、JPEG、PNG、HEIC、DNG、TIF、TIFF、WEBP；同名代理、字幕和元数据等部分关联文件可随素材组处理。厂商专有命名规则仍需逐型号实测，不能据此保证任意设备的所有伴随文件已被完整识别。

拍摄时间目前优先从可识别的文件名推断，否则回退为修改时间，并在界面注明来源。EXIF、QuickTime 容器时间和时区校准尚未实现。顶层批次时间是**导入时间**，内部日期是推断的**拍摄时间**，两者不得混同。

文件引擎使用 SHA-256 做内容核对，SQLite 保存副本、断点和清理记录。路径访问限制在所选根目录内，拒绝越界与符号链接风险。源文件在扫描后变化时，本次旧选择不可直接执行。

## 10. 状态、错误与非功能要求

| 状态或事件 | 用户看到的反馈 | 数据处理要求 |
| --- | --- | --- |
| 等待连接 | 引导插线、切换文件传输或选目录 | 不修改文件 |
| 正在扫描 | 扫描与副本检查状态 | 只读 |
| 正在转存 | 当前文件与进度、暂停入口 | 临时文件及断点持久化 |
| 目标容量不足/写失败 | 明确失败原因，可换目录重试 | 保留源与已完成文件 |
| 设备断开 | 提示重接并重新扫描 | 停止操作，不清理源 |
| 已完成 | 报告复制与校验结果、实际目标路径 | 不自动删源 |
| 清理部分失败 | 报告成功与失败项目 | 不把部分成功说成全部完成 |

性能目标是长列表懒加载、缩略图后台生成、大文件流式校验，避免将整段视频读入主线程。应兼顾系统浅色/深色、可访问名称、文字状态与键盘操作。传输速度和剩余时间尚未有可靠实现，不展示估算值冒充真实数据。

## 11. 当前实现、修正记录与实测

### 11.1 已实现

- SwiftUI Mac 主窗口、三功能入口、媒体日期分组、缩略图、单项预览、时间筛选、目标选择与状态反馈。
- “扫描已连接设备”通过 Disk Arbitration 区分实际外接存储与虚拟磁盘；多候选时由用户选择。
- Mac 端复制、SHA-256 校验、目标范围去重、SQLite 断点和副本记录、独立设备清理流程。
- 路径预览把源文件、Mac 预计或实际目标、PC 与手机规划放到同一条阅读顺序中；PC 与手机明确标注尚未实现。
- 应用 Logo、可重复生成的图标脚本、内嵌引擎的安装包、自动测试与构建工作流。

### 11.2 本轮修正的问题

| 问题 | 修正 | 验证方式 |
| --- | --- | --- |
| 不同目标目录间去重可能误跳过 | 去重校验限定在当前目标目录 | 引擎测试与临时素材烟测 |
| macOS `/var` 与真实路径映射影响测试 | 测试路径使用解析后的真实路径 | 20 项引擎测试通过 |
| 外接磁盘镜像会干扰设备识别 | 仅列出实际外接存储候选 | Action 4 与磁盘镜像同时存在时实测 |
| 转存前难判断文件去哪里 | 显示完整源路径、Mac 目标路径及各端规划 | Action 4 只读扫描后的界面核对 |
| 路径区占用过多高度 | PC/手机规划改为可展开 | 主窗口中仍能直接看到素材列表 |

### 11.3 实机与测试证据

在本机，DJI Osmo Action 4 的 USB 文件传输存储挂载为 `Untitled`；应用只读扫描识别 100 个媒体素材（49 JPG、40 DNG、11 MP4），并显示缩略图和路径。真实相机素材**没有执行复制或清理**，因此这两项实机验收仍未完成。临时测试素材完成了界面复制、目标哈希一致性核对和引擎烟测。Python 引擎 20 项自动测试通过；DMG 构建与镜像校验通过。具体记录见 [VALIDATION.md](../VALIDATION.md)。

## 12. 后续开发路线与验收条件

| 优先级 | 工作 | 完成条件 |
| --- | --- | --- |
| P0 · Mac 稳定性 | 用可丢弃的 Action 4 实物素材验证复制、关联文件、断点、失败恢复与清理；扩展其他相机型号 | 每个型号形成扫描、复制、校验、清理的实际记录；未通过项目明确列出 |
| P0 · 正式分发 | Developer ID 签名、公证、无开发环境 Mac 安装；Intel 与最低系统版本验证 | 可在目标机器正常安装、启动、扫描与转存 |
| P1 · 时间与媒体 | EXIF/QuickTime 时间、时区、专有格式缩略图、更多厂商关联规则 | 文件时间和原片组经样本集核对，无法预览时明确提示 |
| P1 · 路径与状态 | 转存完成后显示批次清单和每个素材的最终路径；改善目标目录切换与多副本展示 | 用户可从界面定位真实文件，预估与执行结果差异有说明 |
| P2 · Windows | 原生或跨平台客户端，磁盘发现、目标目录、复制校验、断点与安全清理 | 与 Mac 归档规则兼容，Windows 实机验收通过 |
| P2 · Android | USB OTG / 文件选择器权限、手机可写目录、复制校验与断点 | 目标设备和 Android 版本矩阵实测；不把受限目录假设为通用路径 |

Windows 和 Android 的技术选型、最低版本、设备协议与发布方式尚未定稿。后续开发应以当前 Mac 行为和测试素材作为可复现基线，而非直接复用桌面路径或权限假设。
